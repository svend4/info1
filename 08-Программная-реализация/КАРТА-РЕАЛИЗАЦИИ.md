## Архитектурные паттерны

### 1. Repository Pattern
- `CardManager` выступает как Repository для `Card` объектов
- Абстрагирует детали хранения (файловая система)

### 2. Dependency Injection
- Все компоненты принимают зависимости через конструкторы
- Минимизация связности (Закон 3)

### 3. Strategy Pattern
- Различные форматы экспорта (JSON, CSV, ZIP)
- Легко добавить новые форматы

### 4. Observer Pattern (неявный)
- Автоматизация отслеживает изменения карточек
- Триггеры напоминаний и уведомлений

### 5. Single Responsibility Principle
- Каждый модуль имеет одну ответственность
- Максимизация когезии (Закон 4)
