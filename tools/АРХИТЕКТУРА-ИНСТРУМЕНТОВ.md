## Компоненты системы

### 1. Подсистема измерения

**Назначение:** Сбор данных о состоянии проекта

**Компоненты:**
- `health_metrics.py` — расчёт метрик CD, VT, CR, DB
- `save_metrics.py` — сохранение истории
- `visualize_connections.py` — визуализация

**Архитектурные решения:**
- Сканирование только .md файлов (осознанное ограничение)
- Извлечение метаданных через регулярные выражения
- Построение графа связей в памяти

⇑ **Трассировка к концепциям:**

- [../ЭТАП-6-САМОСОВЕРШЕНСТВОВАНИЕ.md](../ЭТАП-6-САМОСОВЕРШЕНСТВОВАНИЕ.md) (α=+2) — принцип измеримости

⇓ **Реализация:**

## Архитектурные принципы

### 1. Разделение ответственности

**Принцип:** Каждый инструмент делает одно дело хорошо

⇑ **Философская основа:**
- [../01-Концепция/ПРИНЦИПЫ-И-ПАТТЕРНЫ.md](../01-Концепция/ПРИНЦИПЫ-И-ПАТТЕРНЫ.md) (α=+2) — принцип специализации

**Реализация:**
- `health_metrics.py` — ТОЛЬКО измерение
- `self_improvement.py` — ТОЛЬКО диагностика
- `enrich_alpha.py` — ТОЛЬКО обогащение

**Преимущества:**
- Простота тестирования
- Возможность замены компонентов
- Понятность назначения каждого инструмента

---

### 2. Композиция через файлы

**Принцип:** Инструменты общаются через файловую систему

**Реализация:**
- JSON для структурированных данных
- Markdown для документации
- stdout для консольного вывода

**Преимущества:**
- Независимость от языка программирования
- Простота отладки (можно посмотреть промежуточные файлы)
- Unix-философия: каждый инструмент — фильтр

---

### 3. Идемпотентность

**Принцип:** Повторный запуск даёт тот же результат

**Реализация:**
- `enrich_alpha.py` не добавляет метаданные дважды
- `health_metrics.py` не изменяет состояние проекта
- Все инструменты можно запускать многократно безопасно

⇑ **Философская основа:**
- [../01-Концепция/ФИЛОСОФИЯ-ПРОЕКТА.md](../01-Концепция/ФИЛОСОФИЯ-ПРОЕКТА.md) (α=+3) — принцип стабильности

---

### 4. Самоприменимость

**Принцип:** Инструменты применяют методологию ⇑⇓↔ к себе

**Реализация:**
- Инструменты имеют α-метаданные
- Инструменты имеют статусы ⇑/⇓/↔
- Инструменты измеряются теми же метриками

**Пример рефлексии:**
```python
# health_metrics.py измеряет сам себя:
# - α=-4 (код)
# - Статус: ⇑ ВВЕРХ (инструмент для улучшения методологии)
# - Связи ⇑ к МЕТРИКИ-ЗДОРОВЬЯ.md
```

## Архитектурные ограничения и компромиссы

### Ограничение 1: Сканирование только .md файлов

**Решение:** Осознанное ограничение

**Причины:**
- Простота парсинга
- Метаданные в начале файла
- Единообразный формат

**Компромисс:**
- .py файлы невидимы для метрик
- Решение: создание мостовых .md документов (этот документ!)

⇑ **Документировано в:**
- [../collective_network/ЭТАП-7-ИТОГОВАЯ-СВОДКА.md](../collective_network/ЭТАП-7-ИТОГОВАЯ-СВОДКА.md) — урок #2

---

### Ограничение 2: Регулярные выражения для парсинга

**Решение:** Простота важнее полноты

**Причины:**
- Быстро
- Без зависимостей
- Достаточно для 95% случаев

**Компромисс:**
- Может не поймать сложные форматы
- Решение: EXPLICIT_RULES для особых случаев
