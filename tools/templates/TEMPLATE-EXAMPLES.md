## 💻 Software Project — Пример веб-приложения

### Проект: E-commerce платформа

**Команда создания:**
```bash
python tools/project_template_generator.py --name ecommerce-platform --type software --git --ci
```

### Заполненный ARCHITECTURE-TEMPLATE.md

```markdown
# Архитектура E-commerce платформы
*Уровень абстракции: α=0 (архитектура)*
*Статус: ⇑ ВВЕРХ (от требований к архитектуре)*
*CYCLE: 1*

## 1. Обзор системы

### 1.1 Назначение
Современная e-commerce платформа для продажи товаров онлайн с поддержкой
множественных продавцов (marketplace).

### 1.2 Ключевые функции
- Каталог товаров с поиском и фильтрацией
- Корзина и оформление заказов
- Интеграция с платёжными системами
- Личный кабинет покупателя и продавца
- Система отзывов и рейтингов

## 2. Архитектурный стиль

**Выбран:** Microservices Architecture

**Обоснование:**
- Масштабируемость под высокие нагрузки
- Независимое развертывание сервисов
- Технологическая гетерогенность
- Fault isolation

## 3. Компоненты системы

### 3.1 Frontend
- **Технология:** React 18 + TypeScript
- **State management:** Redux Toolkit
- **UI библиотека:** Material-UI
- **Deployment:** Vercel

### 3.2 Backend Services

#### User Service
- **Назначение:** Управление пользователями, аутентификация
- **Технология:** Node.js + Express
- **База данных:** PostgreSQL
- **Auth:** JWT + OAuth2

#### Product Service
- **Назначение:** Каталог товаров, поиск
- **Технология:** Python + FastAPI
- **База данных:** MongoDB
- **Search:** Elasticsearch

#### Order Service
- **Назначение:** Управление заказами
- **Технология:** Java + Spring Boot
- **База данных:** PostgreSQL
- **Message queue:** RabbitMQ

#### Payment Service
- **Назначение:** Обработка платежей
- **Технология:** Node.js + Express
- **Интеграции:** Stripe, PayPal
- **PCI DSS:** Compliant

### 3.3 Infrastructure
- **API Gateway:** Kong
- **Service mesh:** Istio
- **Monitoring:** Prometheus + Grafana
- **Logging:** ELK Stack
- **CI/CD:** GitHub Actions
- **Container orchestration:** Kubernetes

## 4. Диаграммы

### 4.1 Архитектура высокого уровня
```

   ▼       ▼       ▼         ▼
┌──────┐┌──────┐┌──────┐┌─────────┐
│ User ││Product││Order││ Payment │
│Service││Service││Service││ Service │
└──┬───┘└───┬──┘└───┬──┘└────┬────┘
   │        │       │        │

## 🏥 Healthcare Project — Пример клиники

### Проект: Телемедицина платформа

**Команда создания:**
```bash
python tools/project_template_generator.py --name telemedicine-platform --type healthcare --git --security
```

### Заполненный CLINICAL-PROTOCOL-TEMPLATE.md

```markdown
# Клинический протокол: Удалённая консультация
*Уровень абстракции: α=-1 (протокол)*
*Статус: ⇓ ВНИЗ (от стандартов к процедуре)*
*CYCLE: 1*

## 1. Назначение

Протокол проведения удалённых медицинских консультаций через
телемедицинскую платформу.

## 2. Показания

- Плановые консультации без физического осмотра
- Follow-up визиты после лечения
- Консультации по результатам анализов
- Психологическая поддержка
- Назначение/корректировка терапии

## 3. Противопоказания

- Острые состояния требующие немедленной помощи
- Первичная диагностика серьёзных симптомов
- Необходимость физического осмотра
- Технические ограничения у пациента

## 4. Процедура проведения

### 4.1 Подготовка (5 минут до консультации)

**Врач:**
1. Проверить техническое оборудование
   - Камера работает
   - Микрофон работает
   - Интернет стабилен
2. Ознакомиться с историей болезни пациента
3. Просмотреть результаты анализов

**Пациент:**
1. Подключиться за 5 минут до начала
2. Проверить камеру и микрофон
3. Подготовить вопросы

### 4.2 Начало консультации (2-3 минуты)

1. Идентификация пациента
   - ФИО, дата рождения
   - Проверка через документ
2. Информированное согласие
   - На телемедицинскую консультацию
   - На обработку персональных данных
3. Начало записи (с согласия)

### 4.3 Сбор анамнеза (5-10 минут)

1. Жалобы пациента
2. История текущего заболевания
3. Анамнез жизни
4. Аллергологический анамнез
5. Принимаемые лекарства

### 4.4 Визуальный осмотр (5 минут)

- Общее состояние
- Цвет кожных покровов
- Дыхание
- Показ проблемных зон (при необходимости)

### 4.5 Диагностика (5-10 минут)

1. Анализ симптомов
2. Просмотр результатов обследований
3. Предварительный диагноз
4. План дополнительных обследований (если нужно)

### 4.6 Назначения (5 минут)

1. Медикаментозная терапия
   - Препараты, дозировки
   - Длительность приёма
   - Побочные эффекты
2. Немедикаментозные рекомендации
3. Follow-up план

### 4.7 Завершение (2-3 минуты)

1. Ответы на вопросы пациента
2. Выписка электронного рецепта
3. Назначение следующего визита
4. Окончание записи

## 5. Документация

### 5.1 Обязательные записи

- Протокол консультации
- Электронный рецепт (при назначении)
- Направления на обследования
- Согласия пациента

### 5.2 Хранение

- Видеозапись: 3 года
- Протокол: бессрочно в ЭМК
- Рецепты: 3 года

## 6. Качество и безопасность

### 6.1 Критерии качества

- Консультация длится не менее 15 минут
- Пациент понял рекомендации (обратная связь)
- Документация заполнена полностью
- Технических сбоев не было

### 6.2 Безопасность данных

- Шифрование видеосвязи (end-to-end)
- HIPAA compliance
- Защищенное хранилище записей
- Доступ только авторизованного персонала

## 7. Экстренные ситуации

### 7.1 Признаки экстренного состояния

- Боль в груди
- Затруднённое дыхание
- Потеря сознания
- Сильное кровотечение

### 7.2 Действия

1. Немедленно прекратить консультацию
2. Вызвать скорую помощь
3. Оставаться на связи до приезда скорой
4. Зафиксировать инцидент
```

### Чек-лист для Healthcare проекта
