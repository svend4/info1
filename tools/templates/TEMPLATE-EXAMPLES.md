## 💻 Software Project — Пример веб-приложения

### Проект: E-commerce платформа

**Команда создания:**
```bash
python tools/project_template_generator.py --name ecommerce-platform --type software --git --ci
```

### Заполненный ARCHITECTURE-TEMPLATE.md

```markdown
# Архитектура E-commerce платформы
*Уровень абстракции: α=0 (архитектура)*
*Статус: ⇑ ВВЕРХ (от требований к архитектуре)*
*CYCLE: 1*

## 1. Обзор системы

### 1.1 Назначение
Современная e-commerce платформа для продажи товаров онлайн с поддержкой
множественных продавцов (marketplace).

### 1.2 Ключевые функции
- Каталог товаров с поиском и фильтрацией
- Корзина и оформление заказов
- Интеграция с платёжными системами
- Личный кабинет покупателя и продавца
- Система отзывов и рейтингов

## 2. Архитектурный стиль

**Выбран:** Microservices Architecture

**Обоснование:**
- Масштабируемость под высокие нагрузки
- Независимое развертывание сервисов
- Технологическая гетерогенность
- Fault isolation

## 3. Компоненты системы

### 3.1 Frontend
- **Технология:** React 18 + TypeScript
- **State management:** Redux Toolkit
- **UI библиотека:** Material-UI
- **Deployment:** Vercel

### 3.2 Backend Services

#### User Service
- **Назначение:** Управление пользователями, аутентификация
- **Технология:** Node.js + Express
- **База данных:** PostgreSQL
- **Auth:** JWT + OAuth2

#### Product Service
- **Назначение:** Каталог товаров, поиск
- **Технология:** Python + FastAPI
- **База данных:** MongoDB
- **Search:** Elasticsearch

#### Order Service
- **Назначение:** Управление заказами
- **Технология:** Java + Spring Boot
- **База данных:** PostgreSQL
- **Message queue:** RabbitMQ

#### Payment Service
- **Назначение:** Обработка платежей
- **Технология:** Node.js + Express
- **Интеграции:** Stripe, PayPal
- **PCI DSS:** Compliant

### 3.3 Infrastructure
- **API Gateway:** Kong
- **Service mesh:** Istio
- **Monitoring:** Prometheus + Grafana
- **Logging:** ELK Stack
- **CI/CD:** GitHub Actions
- **Container orchestration:** Kubernetes

## 4. Диаграммы
```

### Проект: Телемедицина платформа

**Команда создания:**
```bash
python tools/project_template_generator.py --name telemedicine-platform --type healthcare --git --security
```

### Заполненный CLINICAL-PROTOCOL-TEMPLATE.md

```markdown
# Клинический протокол: Удалённая консультация
*Уровень абстракции: α=-1 (протокол)*
*Статус: ⇓ ВНИЗ (от стандартов к процедуре)*
*CYCLE: 1*

## 1. Назначение

Протокол проведения удалённых медицинских консультаций через
телемедицинскую платформу.

## 2. Показания

- Плановые консультации без физического осмотра
- Follow-up визиты после лечения
- Консультации по результатам анализов
- Психологическая поддержка
- Назначение/корректировка терапии

## 3. Противопоказания

- Острые состояния требующие немедленной помощи
- Первичная диагностика серьёзных симптомов
- Необходимость физического осмотра
- Технические ограничения у пациента

## 4. Процедура проведения

### 4.1 Подготовка (5 минут до консультации)

**Врач:**
1. Проверить техническое оборудование
   - Камера работает
   - Микрофон работает
   - Интернет стабилен
2. Ознакомиться с историей болезни пациента
3. Просмотреть результаты анализов

**Пациент:**
1. Подключиться за 5 минут до начала
2. Проверить камеру и микрофон
3. Подготовить вопросы

### 4.2 Начало консультации (2-3 минуты)

1. Идентификация пациента
   - ФИО, дата рождения
   - Проверка через документ
2. Информированное согласие
   - На телемедицинскую консультацию
   - На обработку персональных данных
3. Начало записи (с согласия)

### 4.3 Сбор анамнеза (5-10 минут)

1. Жалобы пациента
2. История текущего заболевания
3. Анамнез жизни
4. Аллергологический анамнез
5. Принимаемые лекарства

### 4.4 Визуальный осмотр (5 минут)

- Общее состояние
- Цвет кожных покровов
- Дыхание
- Показ проблемных зон (при необходимости)

### 4.5 Диагностика (5-10 минут)

1. Анализ симптомов
2. Просмотр результатов обследований
3. Предварительный диагноз
4. План дополнительных обследований (если нужно)

### 4.6 Назначения (5 минут)

1. Медикаментозная терапия
   - Препараты, дозировки
   - Длительность приёма
   - Побочные эффекты
2. Немедикаментозные рекомендации
3. Follow-up план

### 4.7 Завершение (2-3 минуты)

1. Ответы на вопросы пациента
2. Выписка электронного рецепта
3. Назначение следующего визита
4. Окончание записи

## 5. Документация

### 5.1 Обязательные записи

- Протокол консультации
- Электронный рецепт (при назначении)
- Направления на обследования
- Согласия пациента

### 5.2 Хранение

- Видеозапись: 3 года
- Протокол: бессрочно в ЭМК
- Рецепты: 3 года

## 6. Качество и безопасность

### 6.1 Критерии качества

- Консультация длится не менее 15 минут
- Пациент понял рекомендации (обратная связь)
- Документация заполнена полностью
- Технических сбоев не было

### 6.2 Безопасность данных

- Шифрование видеосвязи (end-to-end)
- HIPAA compliance
- Защищенное хранилище записей
- Доступ только авторизованного персонала

## 7. Экстренные ситуации

### 7.1 Признаки экстренного состояния

- Боль в груди
- Затруднённое дыхание
- Потеря сознания
- Сильное кровотечение

### 7.2 Действия

1. Немедленно прекратить консультацию
2. Вызвать скорую помощь
3. Оставаться на связи до приезда скорой
4. Зафиксировать инцидент
```

```markdown
### 3.1 Главная цель

### 3.2 Конкретные задачи

## 4. Гипотезы

### 4.1 Основная гипотеза
H₁: Повышенная концентрация микропластика коррелирует со снижением
биомассы и видового разнообразия зоопланктона.

### 4.2 Дополнительные гипотезы
- H₂: Концентрация микропластика выше вблизи городов и портов
- H₃: Доминирующие полимеры — PE и PP (упаковка)
- H₄: Микропластик аккумулируется в организмах планктона

## 5. Методология

### 5.1 Дизайн исследования
**Тип:** Смешанный (полевые наблюдения + лабораторный эксперимент)
**Подход:** Лонгитюдный (2 года, 8 сезонных кампаний)

### 5.2 Район исследования
- **Локация:** Финский залив, Балтийское море
- **Станции:** 15 точек отбора проб
  - 5 вблизи Санкт-Петербурга (урбанизированная зона)
  - 5 в средней части залива
  - 5 в открытых водах (контроль)

### 5.3 Отбор проб

#### Микропластик
- **Метод:** Планктонная сеть (300 мкм), горизонтальный траление
- **Объём:** 100 м³ на станцию
- **Частота:** Ежеквартально (зима, весна, лето, осень)
- **Обработка:** Фильтрация, визуальная сортировка, FTIR спектроскопия

#### Планктон
- **Метод:** Сеть Джеди (100 мкм), вертикальное траление (0-20 м)
- **Объём:** 50 м³ на станцию
- **Анализ:** Микроскопия, подсчёт численности, биомасса (сухой вес)
- **Таксономия:** Идентификация до рода/вида

### 5.4 Лабораторные эксперименты

**Модельный организм:** Daphnia magna (дафния)

**Условия:**
- Концентрации микропластика: 0 (контроль), 10, 100, 1000 частиц/л
- Полимер: Полистирол (PS), размер 10-100 мкм
- Длительность: 21 день
- Повторности: 5 аквариумов на вариант
- Температура: 20±1°C, фотопериод 16:8 (свет:темнота)

**Измерения:**
- Выживаемость (%)
- Плодовитость (потомства на самку)
- Рост (длина тела, мм)
- Аккумуляция пластика (флуоресцентная микроскопия)

### 5.5 Статистический анализ

**Программное обеспечение:** R (версия 4.3+), пакеты: vegan, ggplot2, lme4

**Методы:**
- Описательная статистика (mean ± SD)
- ANOVA / Kruskal-Wallis (сравнение групп)
- Регрессионный анализ (микропластик vs биомасса)
- Многомерный анализ (PCA, NMDS для видового состава)
- Смешанные модели (учёт повторных измерений)

**Критерий значимости:** p < 0.05
```

```markdown
- **Ст. 54.1 НК РФ** — пределы осуществления прав по исчислению налогов

**Судебная практика:**
- Постановление Пленума ВАС РФ № 53 от 12.10.2006 "Об оценке арбитражными судами обоснованности получения налогоплательщиком налоговой выгоды"
- Определение КС РФ № 329-О от 16.10.2003
- Постановления Президиума ВАС РФ (практика по ст. 54.1 НК РФ)

### 3.2 Позиция налогоплательщика

#### Формальные требования соблюдены (ст. 169, 171, 172 НК РФ)

**Аргумент 1:** Наличие всех первичных документов
- Счёт-фактура соответствует требованиям ст. 169 НК РФ (все реквизиты)
- Товар принят к учёту (есть ТОРГ-12)
- Оплата произведена (платёжные поручения)

**Правовое обоснование:**
Согласно ст. 172 НК РФ, вычет НДС предоставляется при наличии счёта-фактуры и
принятии товара к учёту. Формальные условия выполнены.

**Судебная практика:**
- Постановление Президиума ВАС РФ № 2341/12 — "налоговый орган не вправе отказать
в вычете НДС только на основании пороков контрагента, если сам налогоплательщик
не участвовал в схеме уклонения"

#### Должная осмотрительность проявлена

**Аргумент 2:** Клиент проверил контрагента

**Аргумент 3:** Товар фактически получен и использован

**Судебная практика:**
- Постановление АС Уральского округа № Ф09-8765/2025 — "фактическое использование
```

```markdown
## 2. Концепция выставки

### 2.1 Тема
Выставка исследует трансформацию человеческого тела в цифровую эпоху:
- **Биометрия** как новая форма телесности (Face ID, отпечатки пальцев)
- **Аватары** как цифровые двойники (VR, metaverse)
- **Алгоритмы красоты** (фильтры Instagram, AI-generated faces)
- **Surveillance** и тело как данные (камеры, трекинг)

### 2.2 Художественный подход
**Медиум:** Видео-арт + интерактивные инсталляции + генеративное AI-искусство

**Стилистика:**
- Минималистичная эстетика (белые пространства, чистые формы)
- Contrast между органическим и цифровым
- Использование glitch-эстетики (ошибки кодирования как метафора)
- Иммерсивный опыт (зритель как участник, а не наблюдатель)

### 2.3 Философский контекст
**Референсы:**
- Donna Haraway — "Cyborg Manifesto" (гибридность тела и технологии)
- Marshall McLuhan — "The medium is the message"
- Hito Steyerl — исследование образов в цифровую эпоху
- Paul B. Preciado — квир-теория тела

**Ключевые вопросы:**
1. Что значит быть телом, когда твоё тело — это данные?
2. Как технологии переопределяют boundaries (границы) телесного?
3. Возможна ли автономия тела в алгоритмическом капитализме?

## 3. Список произведений

### 3.1 Работа 1: "Лицо как пароль" (Video installation)

**Описание:**
5-канальная видео-инсталляция. На 5 экранах одновременно показаны лица,
проходящие через Face ID сканирование. Постепенно лица превращаются в
биометрические карты (точки, линии, цифры). Сопровождается звуком
сканирования (пикселизированный шум).

**Технические характеристики:**
- 5 экранов 55", установленных в круг (зритель в центре)
- Видео: 4K, 10 минут (loop)
- Звук: 8.1 surround (направленный звук для каждого экрана)

**Размеры:** 5m × 5m площадь инсталляции

**Материалы:**
- Съёмка: iPhone (для аутентичности Face ID)
- Постпродакшн: TouchDesigner (real-time визуализация биометрии)
- Звук: Max/MSP (генеративный саундскейп)

**Смысл:**
Лицо больше не уникальная идентичность, а функциональный инструмент доступа.
Работа задаёт вопрос: кому принадлежит моё лицо — мне или алгоритму?

### 3.2 Работа 2: "Аватар плачет" (Interactive sculpture)

**Описание:**
3D-сканированная скульптура головы художника (в натуральную величину),
напечатанная на 3D-принтере. Из глаз стекает прозрачная жидкость (вода),
которая активируется присутствием зрителя (motion sensor). На лице
проецируются фрагменты текста из социальных сетей (comments, hate speech).

**Технические характеристики:**
- Материал: Прозрачный resin (3D-печать)
- Размеры: 40cm (высота) × 25cm × 30cm
- Система: Arduino + motion sensor + water pump
- Проектор: Pico-projector (встроенный в постамент)

**Звук:** Шёпот (AI-generated голос читает комментарии)

**Смысл:**
Цифровая идентичность (аватар) обретает физическую форму, но остаётся
уязвимой для внешних воздействий. Слёзы — символ того, что эмоции не
исчезают в цифровом, а трансформируются.

### 3.3 Работа 3: "Красота по алгоритму" (Generative AI installation)

**Описание:**
Экран 3m × 2m, на котором в real-time генерируются "идеальные" лица с помощью
StyleGAN3 (AI model). Зритель может взаимодействовать через тач-скрин:
двигать слайдеры (возраст, пол, раса, улыбка, макияж). Лица морфируются
в зависимости от выбора. Параллельно показываются "оценки красоты"
от AI-моделей (Face++, AWS Rekognition).

**Технические характеристики:**
- Дисплей: 3m × 2m LED screen (touch-enabled)
- Компьютер: RTX 4090 (для real-time генерации)
- Софт: StyleGAN3 + custom UI (Python)

**Данные:**
- Датасет: 100,000 лиц из Instagram (скрапленные)
- AI модели: Face++ API, AWS Rekognition

**Смысл:**
Алгоритмы красоты (фильтры, AI-редакторы) создают новые стандарты внешности.
Работа показывает, как технологии формируют наше представление о "норме" и
"идеале". Зритель становится соучастником этого процесса.

### 3.4 Работа 4: "Тело под надзором" (Video mapping)

**Описание:**
Video mapping на 3D-модели человеческого торса (манекен 1.5m).
Проецируются кадры с камер наблюдения: улицы, метро, магазины.
Тело становится экраном, на котором "пишется" история слежки.
Периодически появляются красные квадраты (face recognition tracking).

**Технические характеристики:**
- Манекен: Белый торс (1.5m высота)
- Проектор: 4K, короткофокусный
- Видео: 15 минут (loop)
- Mapping софт: MadMapper

**Материалы:**
- Архив: 50+ часов footage с камер наблюдения (легально получен)
- Постпродакшн: After Effects (tracking визуализация)

**Смысл:**
Тело в публичном пространстве постоянно под надзором. Оно больше не
принадлежит себе, а становится объектом данных для систем контроля.

### 3.5 Работа 5: "Экзоскелет данных" (Mixed media sculpture)

**Описание:**
Скульптура человеческого силуэта (2m), сделанная из серверных плат,
кабелей, SIM-карт. Внутри — LED-подсветка (пульсирует как сердцебиение).
На платах выгравированы фрагменты пользовательских соглашений
(Terms of Service от Google, Facebook, Apple).

**Технические характеристики:**
- Материалы: 200+ старых серверных плат, 500m кабелей
- Размеры: 2m × 1m × 0.5m
- Освещение: RGB LED strips (Arduino-controlled)

**Смысл:**
Наше цифровое тело "носит" экзоскелет из инфраструктуры Big Tech.
Мы зависим от этих систем, но не читаем "инструкции" (T&C).
Работа визуализирует невидимую архитектуру контроля.
```
