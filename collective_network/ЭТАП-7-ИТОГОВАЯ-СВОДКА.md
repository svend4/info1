### v0.9: Прорыв через исправление логики
**Дата:** 2026-01-24  
**Цель:** Снизить DB через исправление концептуальной ошибки

**Результат:**
- VT: 34.88% → 34.88% (0%) ✅ Стабильно
- DB: 107.39% → 78.80% (**-28.59%**) 🎉 ПРОРЫВ!
- Исправлена функция `_extract_direction()` в health_metrics.py
- Добавлено 6 явных статусов "Статус: ⇑/⇓/↔"

**Фундаментальное открытие:** 
> **health_metrics.py определял направление по α-уровню, что концептуально неправильно!**  
> α-уровень = уровень абстракции ≠ направление развития ⇑⇓↔

**Философское обоснование:**
- α-уровень — статический атрибут документа (где он находится в иерархии абстракций)
- Направление ⇑⇓↔ — динамический контекст (как документ развивает проект)
- Документ α=+2 может развиваться в ЛЮБОМ направлении ⇑⇓↔

**Техническое изменение:**
```python
# БЫЛО (неправильно):
if alpha > 0:  return 'up'  # α>0 автоматически → ⇑

# СТАЛО (правильно):
status_match = re.search(r'Статус:.*⇑|⇓|↔', content)
if status_match:  return direction_from_status  # Приоритет явному статусу
```

**Ключевой урок:** Explicit is better than implicit. Направление должно быть явно указано в метаданных.

## Ключевые открытия и уроки

### 1. Фундаментальная ошибка в архитектуре кода

**Проблема:** health_metrics.py v0.8 и ранее определял направление развития (⇑⇓↔) автоматически по α-уровню:
```python
if alpha > 0:  return 'up'
elif alpha < 0:  return 'down'
else:  return 'horizontal'
```

**Почему это неправильно:**
- α-уровень отражает **где** находится документ в иерархии абстракций (статический атрибут)
- Направление ⇑⇓↔ отражает **как** документ развивает проект (динамический контекст)
- Документ α=+2 (законы) может:
  - ⇑ обобщать опыт применения законов
  - ⇓ детализировать, как применять законы на практике
  - ↔ связывать законы с другими концепциями

**Исправление (v0.9):**
- Приоритет 1: Явное поле "Статус: ⇑/⇓/↔" в метаданных
- Приоритет 2: Fallback на α-уровень (для обратной совместимости)
- Приоритет 3: None (направление не определено)

**Философское обоснование:**
> "Уровень абстракции и направление развития — ортогональные концепции.  
> Смешивание их приводит к неправильной интерпретации структуры проекта."

**Эффект исправления:** DB -28.59% (107.39% → 78.80%)

---

### 2. .py файлы невидимы для health_metrics.py

**Проблема:** В v0.8 добавили ~17 вертикальных ссылок, но VT не изменился.

**Причина:** health_metrics.py сканирует ТОЛЬКО .md файлы (строка 109):
```python
md_files = list(self.root.glob("**/*.md"))
```

**Следствия:**
- Связи в .py файлах не учитываются в метриках VT, CD
- Обратные ⇑ ссылки из кода к концепциям невидимы
- Ссылки .md → .py создают "тупиковые" соединения

**Решение:**
- Для повышения VT нужны мостовые .md документы (α=0, α=-1)
- Или расширить health_metrics.py для сканирования .py файлов
- Или создать .md обёртки для ключевых инструментов

**Ключевой урок:** Инструмент измерения определяет, что измеряется. Невидимые для инструмента связи не влияют на метрики.

### Приоритет 4: Автоматизация добавления статусов

**Проблема:** Ручное добавление статусов трудоёмко

**Решение:** Создать инструмент `tools/infer_direction.py`:

**Функционал:**
1. Анализирует содержимое документа
2. Предлагает направление ⇑/⇓/↔ на основе:
   - Ключевых слов ("обобщает", "детализирует", "связывает")
   - Структуры связей (много ссылок вверх → ⇑, вниз → ⇓)
   - Типа документа (README → ⇓, INDEX → ↔)
3. Генерирует предложение: "Рекомендуемый статус: ⇓ ВНИЗ"
4. Позволяет пользователю подтвердить или изменить

**Пример использования:**
```bash
$ python3 tools/infer_direction.py --suggest QUICKSTART.md
Анализ: QUICKSTART.md
  - Тип: руководство (quick start)
  - α-уровень: -2 (примеры)
  - Ключевые слова: "быстрый старт", "руководство"
  
Рекомендация: ⇓ ВНИЗ (детализация)
Применить? [y/n]: y
✓ Добавлен статус к QUICKSTART.md
```

**Преимущества:**
- Ускоряет процесс балансировки
- Снижает ошибки классификации
- Может быть запущен на всех документах без статуса
