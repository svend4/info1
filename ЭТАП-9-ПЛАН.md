## 🚀 Фазы реализации

**Цель:** Минимальный рабочий прототип NLP-интерфейса

**Задачи:**
1. ✅ Создать план ЭТАПА 9 (этот документ)

3. ⏳ Создать rule-based классификатор типов проектов
4. ⏳ Интегрировать с существующим генератором
5. ⏳ Протестировать на 10-20 примерах

**Технологии:**
- Python NLP: spaCy или NLTK для базовой обработки текста
- Rule-based классификация (без ML на первом этапе)
- Keyword matching для определения типа проекта

**Критерии успеха:**
- [ ] Система понимает простые описания типа "Создай веб-приложение"

- [ ] Интеграция с project_template_generator.py работает

### Фаза 2: ML-классификация (Week 3-4)

**Цель:** Заменить rule-based подход на ML-модели

**Задачи:**

### 1. Какой минимальный набор информации нужен для качественной генерации?

**Гипотеза:** Достаточно 2-3 предложений описания проекта

**Эксперимент:**
- Собрать примеры с разной длиной описаний (1-10 предложений)
- Измерить качество генерации в зависимости от длины
- Найти оптимальную длину

### 2. Можно ли улучшить качество через интерактивный диалог?

**Гипотеза:** Clarifying questions повышают точность на 15-20%

**Эксперимент:**
- A/B тест: one-shot vs conversational generation
- Измерить user satisfaction в обеих группах

**Подход:** Качественное исследование
- Собрать 100 примеров описаний от реальных пользователей
- Извлечь паттерны и общие фразы
- Создать таксономию типичных описаний

## 📚 Датасет для обучения

### Структура

Каждый пример включает:
```json
{
  "id": "001",
  "description": "Хочу создать мобильное приложение для учёта финансов",
  "labels": {
    "primary_type": "software",
    "secondary_types": ["finance"],
    "scale": "small",
    "features": ["mobile", "финансы", "учёт"]
  },
  "extracted_params": {
    "platform": "mobile",
    "domain": "finance"
  }
}
```

### План сбора

1. **Seed data (50 примеров)** — вручную создать базовые примеры
2. **Synthetic data (150 примеров)** — генерация через LLM с вариациями
3. **User data (100+ примеров)** — сбор от реальных пользователей
4. **Augmentation** — paraphrasing для увеличения датасета

### Покрытие

Минимум **15 примеров на каждый из 16 типов** = 240 примеров
Дополнительно **50 примеров multi-domain** = 290 примеров total

## 🎓 Обучение и тюнинг

### Baseline (Rule-based)

Простые правила на основе keywords:
```python
KEYWORDS = {
    'software': ['приложение', 'сайт', 'веб', 'api', 'backend', 'frontend'],
    'research': ['исследование', 'эксперимент', 'гипотеза', 'данные'],
    'business': ['бизнес', 'стартап', 'компания', 'продажи'],
    # ... для всех 16 типов
}
```

**Ожидаемая точность:** 60-70%

---

### ML Model (DistilBERT)

Fine-tuning DistilBERT на русском языке:
```python
from transformers import DistilBertForSequenceClassification

model = DistilBertForSequenceClassification.from_pretrained(
    'distilbert-base-multilingual-cased',
    num_labels=16  # 16 типов проектов
)
```

**Гиперпараметры:**
- Learning rate: 2e-5
- Batch size: 16
- Epochs: 3-5
- Optimizer: AdamW

**Ожидаемая точность:** 85-95%

---

### LLM-based (Zero-shot / Few-shot)

Использование Claude API для классификации:
```python
prompt = f"""
Проанализируй описание проекта и определи его тип.

Доступные типы: software, research, business, education, legal,
healthcare, arts, finance, government, nonprofit, manufacturing,
agriculture, sports, hospitality, retail, hobby

Описание: {user_description}

Выведи JSON:
{{
  "primary_type": "...",
  "confidence": 0.95,
  "reasoning": "..."
}}
"""
```

**Ожидаемая точность:** 95%+ (но дороже по cost)
